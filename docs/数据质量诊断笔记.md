# 数据质量诊断笔记

> 本项目最有价值的部分**不是分析结论，而是对数据本身的体检**。
> 这里完整记录：我如何发现数据问题、如何证伪自己的假设、以及哪些问题**目前还无法解决**。
> 最近更新：2026-10-14

---

## 一、背景

原始数据由 `src/spider_real.py` 采集：遍历 10 个城市的景点列表页，
再逐个访问详情页与评论 API，最终得到 **499 条记录 / 21 个字段**。

在清洗阶段我发现：**列表页除本城景点外，还混有周边地区的推荐景点**，
导致「非本地景点被归到本城」的跨城市污染。

---

## 二、字段可信度审计（先搞清楚哪些字段能信）

数据清洗的前提是**知道每个字段的来源**。逐字段核对 `spider_real.py` 后结论如下：

| 字段 | 可信？ | 来源 |
|---|---|---|
| `name` / `rating` / `comment_count` / `price` / `level` / `open_time` / `tags` | ✅ | 详情页解析 |
| `description` | ✅ | 详情页解析（**同时可作定位证据**） |
| `all_comments` | ✅ | 评论 API `sightCommentList.json` |
| `sight_id` / `detail_url` | ✅ | 列表页 |
| `city` | ❌ | **=「所属列表页城市」**，推荐景点会错归 |
| `address` | 🟡 | 详情页正则 `位置：(...)查看地图`；**取不到时退化为 `{城市}市`** |
| `latitude` / `longitude` | ❌ | ⚠️ **城市中心 ± 0.4° 随机生成**（站点未暴露坐标） |
| `distance` | ❌ | ⚠️ **随机数**（2~75km） |

> ⚠️ **结论**：`latitude`/`longitude`/`distance` **不可用于任何分析**。
> 这也是 `scenic_map.html` 只能"形式演示"的原因。

---

## 三、污染检测：三个信号，谁最有效？

| 方法 | 命中记录 | 评价 |
|---|---|---|
| **`sight_id` 跨城市去重** | **123 条**（97 组） | ⭐ **最硬**：同 ID + 同评论数 + 同 URL ⇒ 是同一景点被抓了多次 |
| 名称含其他城市名 | 32 条 | 直观，但漏掉"都江堰""青城山"这类不含城名的 |
| `description` 省份锚定提取 | 67 条 | 精度尚可；⚠️ 覆盖率仅 13.4% |
| ~~经纬度反查~~ | 0 条 | ❌ **前提不成立**（坐标本身是随机生成的） |

**⭐ 一个被主动推翻的方案**：最初计划用经纬度反查城市（看似"严谨一个量级"），
但发现**同一景点在不同城市列表页里竟有两套不同坐标**——
进一步读源码才确认：**坐标是随机生成的**。
⇒ **用随机数去校验错误标签，逻辑上无效。方案作废。**

---

## 四、污染规模（硬证据）

```
原始记录              499
唯一 sight_id          376     ⇒  123 条（24.6%）为跨城市重复
```

**清洗后（现行 455 条口径）仍残留**：
- 70 个 `sight_id` 跨城市重复，涉及 **160 条（35.2%）**
- 例：南京的 38 条中约 21 条并非南京（含上海迪士尼、杭州宋城、苏州拙政园、虎丘、周庄…）

⇒ **现行"污染率 8.8%"是明显低估。**

---

## 五、无法解决的问题（诚实记录）

1. **彻底判定城市归属需要外部权威数据**。现有字段中：
   - `city`/`address`/坐标 都不可靠
   - 只有 `description` 能提供部分线索（覆盖率 13.4%）
   ⇒ 剩下的记录**无法 100% 判定**。
2. **重新采集无法解决**：2026-10-14 实测，列表页仍会混入周边地区景点
   （武汉列表页含庐山/滕王阁/岳阳楼），**同一数据源、同一推荐机制**。
   且旧详情页 URL 已 404（站点改用了新的 ID 方案）。
3. **去重法的固有局限**：只能解决"同一景点出现多次"，
   解决不了"只在错误城市出现一次"的景点（如武汉列表里的庐山）。

⇒ 因此本案的定位是「**显著降低污染**」而非「彻底消除污染」。

---

## 六、修复方案与影响

**方案**：按 `sight_id` 跨城市去重，保留「城市内列表位置最靠前」的一条。
依据：城市列表页中，本城景点位于前部、推荐来的外地景点位于尾部（已实测验证）。

| | 现状 | 修复后 |
|---|---|---|
| 总记录数 | 455 | **376** |
| 跨城市重复 | 160 条 | **0** |
| 城市口碑第一名 | 上海 | **南京** ⚠️ 排名翻转 |

⚠️ **排名翻转说明原结论不稳健**，这正是数据清洗重要性的直接证据。

---

## 七、方法论总结

1. **先审计字段可信度，再做清洗** —— 否则等于拿错字段校验错字段
2. **主动证伪自己的方案** —— 经纬度反查看起来更严谨，但前提不成立
3. **用最硬的证据定规模** —— `sight_id` 优于任何基于文本的启发式
4. **量化影响** —— 不只说"清洗了 N 条"，还要说"结论因此改变了什么"
5. **诚实声明边界** —— 明确列出无法解决的问题，不假装完美
