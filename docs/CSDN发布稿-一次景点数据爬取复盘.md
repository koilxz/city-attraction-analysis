一次景点数据爬取复盘：从 499 条到 455 条，我剔掉的 8.8% 脏数据

> 一个真实的数据分析项目复盘：从爬虫到清洗，我是怎么发现并修掉两批脏数据的。完整代码：https://github.com/koilxz/city-attraction-analysis

## 起因：一个看起来很简单的作业

大二实训，题目是"爬取旅游景点数据并做可视化分析"。

任务很朴素：爬 10 个热门旅游城市的景点数据，看看有什么规律。

我选了去哪儿网，写了爬虫，跑了一晚上，拿到了 **499 条**数据。城市覆盖北京、上海、武汉、成都、西安、重庆、青岛、杭州、济南、南京，每条记录包含评分、评论数、门票价格、标签、地址、景区等级等 20 多个字段。

当时我觉得：数据到手了，画几张图，交作业完事。

**但我错得很离谱。**

## 第一个坑：网站塞给我的不是我要的数据

画图之前，我随手看了一眼数据，发现一个奇怪的东西：

> 济南的景点列表里，赫然出现了**泰山**、**故宫**、**八达岭长城**。

等等？泰山在泰安，故宫在北京，跟济南有什么关系？

再往下翻：

- 杭州的数据里混进了 **兵马俑**（西安）、**黄鹤楼**（武汉）
- 南京的数据里混进了 **黄山**、**壶口瀑布**（山西）
- 青岛的数据里混进了 **趵突泉**（济南）

**问题定位**：我写爬虫时是解析列表页的，而旅游网站的列表页底部通常有「相关推荐」「猜你喜欢」模块。这些推荐位的内容也被我的爬虫无差别抓取了进来。

**这是爬虫开发里非常经典的一类 bug**——你以为是选择器写错了，其实是你抓的**页面区域超出了你的预期范围**。

### 怎么修：用"地标 → 城市"映射表做交叉校验

我没有简单粗暴地按关键词过滤，而是建了一张**地标映射表**：

```python
LANDMARKS = {
    "兵马俑": "西安", "秦始皇帝陵": "西安",
    "黄鹤楼": "武汉",
    "东方明珠": "上海", "外滩": "上海",
    "西湖": "杭州", "灵隐寺": "杭州", "千岛湖": "杭州",
    "中山陵": "南京", "明孝陵": "南京", "总统府": "南京",
    "故宫": "北京", "八达岭": "北京", "天安门": "北京",
    "泰山": "泰安",          # 不属于济南/青岛
    "黄山": "黄山", "西递": "黄山",   # 不属于南京/杭州
    "趵突泉": "济南", "大明湖": "济南",
    # ... 共 40+ 个知名地标
}

def guess_real_city(name):
    """根据景点名称猜它真实所在的城市"""
    for kw, city in LANDMARKS.items():
        if kw in str(name):
            return city
    return None
```

然后做**交叉校验**：如果一条记录名称里命中了某地标，但它的 `city` 字段跟地标的真实城市对不上，就判定为**污染数据**。

```python
df["_real_city"] = df["name"].apply(guess_real_city)
polluted = df[(df["_real_city"].notna()) & (df["_real_city"] != df["city"])]
```

**结果检出 44 条污染记录，占总数的 8.8%。**

| 受影响城市 | 污染条数 |
|---|---|
| 南京 | 11 |
| 济南 | 11 |
| 杭州 | 8 |
| 青岛 | 6 |
| 上海 | 5 |
| 重庆 | 3 |

**这 44 条如果不剔除，后面所有"城市排名"的结论全是错的**——因为济南的评分里混进了泰山，南京的评分里混进了黄山，城市的"平均水平"被其他城市的景点拉偏了。

## 第二个坑：0 分不是"差评"，是"没人评"

清理完污染数据，我又看了一遍评分分布，发现了一个更隐蔽的问题：

**有一批景点的评分是 0.0 分。**

在 5 分制的评分体系里，0 分意味着一星都没有——但仔细看这些记录，发现它们有个**共同特征**：

```
城市          名称                        评分    评论数
重庆    中泰天心佛文化旅游景区            0.0      0
北京    北京蜂王谷旅游景区                0.0      0
武汉    《洞庭幻境》                      0.0      0
西安    西安比亚迪二厂员工-2号食堂        0.0      0   ← 这是景点吗？
上海    德必上海书城WE                    0.0      0
```

**评论数全是 0。**

→ 这些景点**从来没有被任何人评价过**。0 分不是"评价很差"，而是平台把「没有评分」这个**缺失值伪编码成了 0**。

### 为什么这个 bug 很危险

因为它是**静默的**——程序不报错，`df["rating"].mean()` 照样能跑出一个数，但这个数是错的：

- 13 条 0 分混在 455 条里，直接把全网均分从 **4.53 拉到 4.40**
- 更糟的是，它会**扭曲城市排名**：哪个城市伪零分多，排名就被拉得越低

### 怎么修：先判"缺失"，再按城市均值填补

```python
# 评分=0 且 评论=0 → 这是缺失值，不是真·0分，先置为缺失
mask = (df["rating"] == 0) & (df["comment_count"] == 0)
df.loc[mask, "rating"] = None

# 再按城市均值填补（保留样本，又不引入跨城市偏差）
df["rating"] = df.groupby("city")["rating"].transform(lambda x: x.fillna(x.mean()))
df["rating"] = df["rating"].fillna(df["rating"].mean())
```

**修正前后对比，影响很直观：**

| 指标 | 修正前 | 修正后 |
|---|---|---|
| 评分范围 | 0.00 ~ 5.00 ❌ | **1.00 ~ 5.00** ✅ |
| 全网均分 | 4.40（被拉低） | **4.53** |
| 城市均分第一名 | 南京 4.61 | **上海 4.62**（南京降至第二） |
| 免费 vs 收费景点均分 | 4.38 / 4.57 | **4.53 / 4.57** |
| 价格-评分相关系数 | −0.03 | **−0.163** |

**排名直接易主了**——这就是脏数据的威力。

## 清洗完之后，数据告诉了我什么

两轮清洗后，499 条变成 **455 条干净数据**。基于它，我得到三个结论：

### 结论 1：门票价格和口碑，几乎没有关系

- 价格与评分的皮尔逊相关系数 = **−0.163**（弱负相关，甚至方向是"越贵口碑略低"）
- 免费景点均分 **4.53**，收费景点均分 **4.57**
- 独立样本 t 检验：**p = 0.709 > 0.05，差异不显著**

> **贵的门票买不到更好的口碑。** 西湖、外滩、天安门这些免费景点的口碑，并不比收费景点差。
> 而且这个结论**在清洗掉 13 条伪零分数据后依然成立**——说明它足够稳健。

### 结论 2：热度高 ≠ 评价好

- 评论数与评分的相关系数 = **0.151**（极弱正相关）

> 评论多的景点不一定评分高。热度反映的是"知名度"，不是"满意度"。有些景点人山人海，纯粹因为它是地标。

### 结论 3：各城市口碑差异明显

| 城市 | 景点数 | 平均评分 |
|---|---|---|
| **上海** | 45 | **4.62** |
| 南京 | 38 | 4.61 |
| 成都 | 50 | 4.59 |
| 北京 | 50 | 4.57 |
| 杭州 | 42 | 4.55 |
| 青岛 | 44 | 4.53 |
| 济南 | 39 | 4.49 |

## 诚实说明：这个项目有哪些局限

一个负责任的分析必须说清楚自己的边界：

1. **价格数据严重不完整**：455 条里只有 36 条有有效价格（几乎全是南京）。所以**"价格与口碑无关"这个结论要谨慎**——它成立的前提是"现有价格数据下"，不是"普遍真理"。
2. **单一平台偏差**：数据只来自去哪儿网，不同平台的评分体系不同。
3. **样本量有限**：455 条对全国景点代表性有限。
4. **评分填补带来轻微偏差**：32 条缺失评分（含 13 条伪零分）用城市均值填补，会略微压缩这些城市的评分方差——这是"保留样本"和"保持真实分布"之间的权衡。
5. **情感分析用的是通用模型**（SnowNLP），未针对旅游语料微调。

**把这些写出来，比藏起来更专业。** 面试官问你"这个结论可靠吗"，你有现成的答案。

## 我学到的三件事

1. **爬虫最大的坑不是反爬，是"抓错了页面区域"。** 列表页的推荐位、广告位、底部导航，都可能在你不知情时混进数据。写完爬虫一定要**肉眼抽查**几条，而不是直接进入分析。

2. **`0` 和"缺失"是两回事。** 数值型字段里，0 经常是"没有数据"的伪装。看到 0 分、0 元、0 长度这类"边界值"，先怀疑它是不是缺失值。

3. **数据清洗不是附带步骤，它就是分析本身。** 这个项目里，最有价值的不是那三个结论，而是"我发现了 8.8% 的污染数据 + 13 条伪零分"这个过程。**结论可能是常识，但发现问题的能力是硬通货。**

## 技术栈与代码

| 环节 | 工具 |
|---|---|
| 数据采集 | `requests` + UA 池 + 重试机制 + 评论 API |

**完整代码**：https://github.com/koilxz/city-attraction-analysis

项目结构：

```
├── src/clean.py        # 清洗（跨城市污染检测 + 伪零分修正）
├── src/visualize.py    # 可视化（只读清洗后的数据）
├── data/raw/           # 原始数据 499 条
├── data/processed/     # 清洗后 455 条 + 质量报告
└── results/figures/    # 11 张图表
```

> 设计上刻意做了**清洗与可视化分离**：`clean.py` 只负责把数据弄干净，`visualize.py` 只负责画图。这样改清洗规则不会污染绘图逻辑，改图也不用重跑爬虫。
