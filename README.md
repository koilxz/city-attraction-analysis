# 10 个热门旅游城市：景点口碑分析（附一次深度数据质量审计）

![Python](https://img.shields.io/badge/Python-3.10+-3776AB?logo=python&logoColor=white)
![pandas](https://img.shields.io/badge/pandas-数据分析-150458?logo=pandas&logoColor=white)
![matplotlib](https://img.shields.io/badge/matplotlib-可视化-11557C)
![License](https://img.shields.io/badge/License-MIT-green)

> 用 Python 采集去哪儿网 10 个热门旅游城市的景点数据，回答：
> **哪个城市的景点口碑最稳？热度高的景点评价一定更好吗？**

**技术栈**：Python · requests · pandas · matplotlib / seaborn · jieba · WordCloud · folium
**分析产物**：12 张静态图表 + 1 个交互式地图（HTML）
**数据规模**：原始 **499** 条 → 清洗后 **151 个景点**（剔除 348 条，保留率 30.3%）

> ⭐ **这个项目最花时间的不是分析，而是搞清楚"哪些数据能信"**。
> 采集回来的 499 条里，**有 70% 根本不在它被标注的那座城市**；
> 另有 **3 个字段是从未存在的伪造数据** —— 见下文。

📝 **技术复盘文章（CSDN）**：[一次景点数据爬取复盘](https://blog.csdn.net/2401_86734821/article/details/167659876)
> ⚠️ 该文写于**清洗 v1 阶段**（当时口径为 455 条 / 污染率 8.8%）。
> 后续两轮深度复检发现污染规模远超该口径，**本 README 的口径最新**。

## ⭐ 一、数据质量审计（本项目核心）

### 1.1 先搞清楚：每个字段是怎么来的？

**做任何清洗之前，必须先知道字段的来源**。逐行核对 `src/spider_real.py` 后：

| 字段 | 可信？ | 来源 / 说明 |
|---|---|---|
| `name` `rating` `comment_count` `price` `level` `open_time` `tags` `description` | ✅ | 详情页解析 |
| `all_comments` | ✅ | 评论 API `sightCommentList.json` |
| `sight_id` `detail_url` | ✅ | 列表页 |
| `city` | ❌ | **=「所属列表页城市」**——列表页会混入周边地区景点 |
| `address` | 🟡 | 详情页正则提取；**取不到时退化为 `{城市}市`** |
| `latitude` `longitude` | ❌ | ⚠️ **城市中心 ± 0.4° 随机生成**（站点未暴露坐标） |
| `distance` | ❌ | ⚠️ **随机数**（2~75km） |

⇒ **后三个字段不是"脏数据"，而是"从不存在的假数据"**，已从数据集中**直接删除**。

### 1.2 一个被我自己推翻的方案

最初我打算用**经纬度反查城市**来校验归属（听起来比关键词法"严谨一个量级"）。
但复核时发现：**同一个景点在不同城市的列表页里，竟有两套完全不同的坐标**：

| 景点 | 标注城市 | address | 坐标 |
|---|---|---|---|
| 成都大熊猫繁育研究基地 | 重庆 | 重庆市 | (29.254, 106.303) |
| 成都大熊猫繁育研究基地 | 成都 | 成都市 | (30.299, 104.451) |

一路查到源码才确认：**坐标是围绕城市中心随机生成的**。
⇒ 用随机数去校验错误标签，逻辑上无效，**方案作废**。

### 1.3 跨城市污染：比原先估计的严重得多

**最硬的证据是 `sight_id`**：同一景点被重复抓进多个城市的列表页时，
它的 `sight_id`、`comment_count`、`detail_url` **完全相同**：

```
原始记录            499
唯一 sight_id       376     ⇒ 123 条（24.6%）是「同一景点出现在多个城市」
清洗前 455 条口径下        ⇒ 仍残留 160 条（35.2%）跨城市重复
```

**污染长什么样**（清洗前南京的 38 条里，约 21 条其实不在南京）：
上海迪士尼、杭州宋城、苏州拙政园、虎丘、周庄、狮子林、黄山、兵马俑……

**检测方法对比**（哪个真的有用）：

| 方法 | 命中 | 评价 |
|---|---|---|
| **`sight_id` 跨城市去重** | **123 条** | ⭐ 最硬，无需任何语义判断 |
| 简介定位信号（"位于 XX 省/市"） | 96 条 | 精度高、覆盖率有限 |
| 名称含外地地名 | 32 条 | 直观，但漏掉"都江堰""青城山"这类 |
| ~~经纬度反查~~ | 0 条 | ❌ 前提不成立 |

### 1.4 更隐蔽的第二类污染：景点名里"看不见城市"

第一类污染靠 `sight_id` 就能抓出来。但**复核清洗结果时发现还有一大批漏网的**：

| 被标注为 | 实际所在的景点（部分） |
|---|---|
| 青岛 | 蜈支洲岛（三亚）、稻城亚丁（甘孜）、蓬莱阁 / 长岛（烟台）、刘公岛 / 成山头（威海）、孔庙 / 孔府 / 尼山圣境（济宁曲阜）、沂蒙山 / 地下大峡谷（临沂） |
| 西安 | 华山（渭南）、太白山 / 关山草原（宝鸡）、乾陵 / 汉阳陵 / 茂陵（咸阳）、野人谷 / 武当一梦（**湖北十堰**） |
| 武汉 | 神农顶 / 大九湖 / 神农架（神农架林区）、隐水洞 / 九宫山（咸宁） |
| 成都 | 乐山大佛 / 峨眉山（乐山）、九寨沟（阿坝州）、绵阳系列（绵阳）、蜀南竹海（宜宾） |
| 杭州 | 虎丘 / 狮子林 / 留园 / 寒山寺 / 周庄（苏州）、安吉系列（湖州）、缙云仙都（丽水） |
| 北京 | 北戴河 / 老龙头 / 鸽子窝（秦皇岛）、易水湖 / 百里峡（保定）、五台山 / 芦芽山（山西忻州） |
| 重庆 | 武陵源 / 黄龙洞（张家界）、凤凰古城 / 红石林（湘西州）、宝箴塞 / 清水溪（**四川广安**） |

**为什么常规规则一条都抓不到**：
- 景点名里**不含**其他城市名（"神农顶风景区"这五个字里没有"神农架"）；
- 简介的行政区信号**与标注城市同省**（武汉与神农架同属湖北 ⇒ 省级校验轻松通过）；
- 这些景点**只出现在一张列表页里**，所以 `sight_id` 去重也碰不到。

⇒ **只能逐条人工判定**。我把剩余 279 个景点全部核验一遍，将其中
**128 个明确在外地的景点**整理成一张可审计的映射表
[`src/foreign_map.py`](src/foreign_map.py)（**景点全名** → 真实城市/省）。
⚠️ 刻意采用**精确匹配**而非关键词匹配 —— 否则"五华山旅游区"会被"华山"误判成渭南。

### 1.5 清洗策略（v3）

1. **字段审计** → 删除伪造字段（`latitude` / `longitude` / `distance`）
2. **用 `description` 提取定位信号**（锚定动词「位于 / 坐落于 / 隶属 / 屹立于 …」后的省份或城市）
3. **按 `sight_id` 跨城市去重**：
   - 若组内所有副本都不属于其标注城市 → **整组剔除**
     （如「拙政园」同时出现在杭州/上海/南京，但它其实在苏州）
   - 否则剔除"外地副本"，从剩下的里选真身
4. **单条记录**：名称/简介/地标/**核验表**与标注城市冲突 → 剔除
5. **常规修复**：伪零分（评分=0 且评论=0 → 缺失）按城市均值填补、派生字段

| 杭州 | 50 | **17** | 南京 | 49 | **16** |

> 剔除的 348 条中：**167 条**是跨城市重复的副本，**181 条**是单条记录的归属冲突
> （其中 156 条由 `foreign_map.py` 核验表判定）。

## 三、两个关键发现

> 以下统计均基于清洗后的 **151 条**数据。评分与评论数字段经审计为**真实可信**。

### 发现 1：热度高 ≠ 评价好

- 评论数与评分的相关系数 **r = 0.101**（Spearman ρ = 0.078，**p = 0.340，不显著**）
- 高热度组（Top 20%，n=31）均分 **4.671**，低热度组（Bottom 20%，n=46）均分 **4.646**，**p = 0.630，不显著**

> **结论**：评论多的景点评分并不明显更高。热度反映的是"知名度"，而非"满意度"——
> 有些景点人多，纯粹因为它是个地标（如兵马俑 66,274 条评论、评分 4.7），而不是因为它好玩。

### 发现 2：各城市口碑有差异，但都在高位

| 排名 | 城市 | 景点数 | 平均评分 |
|---|---|---|---|
| 1 | **成都** | 13 | **4.667** |
| 2 | 上海 | 15 | 4.650 |
| 3 | 北京 | 14 | 4.644 |
| 4 | 青岛 | 11 | 4.630 |
| 5 | 武汉 | 15 | 4.609 |
| 6 | 南京 | 16 | 4.581 |
| 7 | 杭州 | 17 | 4.500 |
| 8 | 重庆 | 16 | 4.485 |
| 9 | 西安 | 18 | 4.419 |
| 10 | **济南** | 16 | **4.400** |

> 全网均分 **4.550**，**77.5%** 的景点评分 ≥ 4.5 —— 整体都在高分区间，
> **城市间差距（4.40 ~ 4.67）其实很小**，不宜过度解读排名。

### ⚠️ 关于"门票价格 vs 口碑"：本数据无法回答

原计划分析"门票越贵口碑是否越好"。但审计后发现：
**499 条中仅 49 条有非零价格，且清洗后只剩 13 条**（其余 `price=0`
混杂了"真免费"与"解析失败"两种含义，无法区分）。

⇒ **13 个样本不足以支撑任何相关性结论，故本项目不给出该结论**。
这是诚实的边界，而不是"结论不显著"。

## 五、⚠️ 局限性（诚实说明）

1. **价格字段不可用**：仅 13 条有有效价格，且 `price=0` 混合了"免费"与"解析失败"。**价格相关的分析无法进行**。
2. **污染按"有证据才删"的原则清理，但非 100% 保证**：`foreign_map.py` 只收录
   **名称或简介能判定归属**的景点。少数简介缺失、名称又无地域信号的记录
   （如"五华山旅游区""际华园·水晶谷"）无法判定，**予以保留**（宁可少删，不可误删）。
   彻底解决需要外部 POI 权威库或按正确归属重新采集。
3. **重新采集无法解决**：2026-10 实测，列表页**仍会混入周边地区景点**（同一推荐机制），
   且旧详情页 URL 已 404。故本项目的定位是"**显著降低污染 + 如实标注残留**"，而非"彻底消除"。
4. **坐标与距离已删除**：站点未暴露经纬度，原脚本用随机数填充。
   本项目**不做景点级地理可视化**；交互地图改为「**城市级聚合**」（城市中心坐标真实可靠）。
5. **单一平台偏差**：数据仅来自去哪儿网，评分体系可能与其他平台不同。
6. **评分填补带来轻微偏差**：缺失评分（含 11 条伪零分）用**城市均值**填补，会略微压缩方差。
7. **情感分析用通用模型**（SnowNLP），未针对旅游语料微调。
8. **评论数作为"热度"代理指标**，受平台流量影响，不完全等于真实客流。
9. **景点粒度不完全统一**：数据集以去哪儿"门票页"为粒度，同一景区的不同子项目
   （如"成都天台山旅游景区-观景台 / -黑龙潭"、"西安城墙 / 西安城墙永宁门智能游船"）
   可能各占一条。合并需人为定义边界与评论数口径，故**未合并**，分析时按"条"计数。
10. **46 个景点评论数为 0**（占 30%）：它们有评分但没爬到评论文本，
    对"热度"分析贡献有限（评分仍参与城市均值计算）。
